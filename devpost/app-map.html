A few pieces, with different responsibilities.

Browser workspace

React forms and a timeline describe creative intent and show status. A browser refresh does not own or cancel the server's work.

Durable server

Fastify routes, SQLite and per-project media keep requests, edit contexts and history distinct. Native jobs have captured identities and resource ownership.

Creative tools

Codex or Claude uses its normal tools to drive YuE2 and Comfy/H3. Librosa analyses the song; FFmpeg assembles the edit. Receipts are checked independently.

The server runs on one Ubuntu/NVIDIA machine; the browser can be elsewhere on a trusted LAN. Project folders organise work, not agent permissions. This prototype has no application accounts.

Scope → requirement → specification → evidence.

“Let people remove clips and bring them back” is a useful intention, but leaves consequential behavior unwritten. Each document answers a different question.

01 / Scope · What belongs?

Iteration without an undo system.

The scope keeps archive/restore, irreversible full-media deletion and retained provenance. History deletion and a general undo/editor system stay out. This protects a bounded creative loop instead of asking agents to build every plausible editor feature.

02 / PRD · What must the user observe?

A stays unplaced. B stays unchanged.

PRD A8/A9 give an example: place A, archive A, put B in that interval, then restore A. A returns to the library, not the sequence. B, coverage and the current render do not change. That is an acceptance result, not a database design.

03 / Spec · How will it be made true?

Separate source, placement and lifecycle.

Spec C8 separates an immutable generated artifact from editable placements. Archive removes placements transactionally; restore changes visibility only. C2 supplies the authoritative mutation boundary. Durable purge, not just “unlink the MP4”, handles permanent deletion.

04 / Tests & observation · What establishes it?

Check the example, then inspect the output.

The store test exercises A→archive→B→restore A, including saved trims/audio/origin. Slice 8 also ran the actual browser scenario and independently decoded a separate post-restore render: the picture/audio and B's media stayed unchanged.

A practice to reuse: turn the ambiguous verb into a small “before → action → after” example first. Then choose the representation and checks that can enforce it. A long vision document would not, by itself, decide whether Restore silently displaces B.

Follow Archive through three code stops.

This is a reference route, not a record of an interactive walkthrough. No edit or destructive action is required to read it. If trying the example later, use disposable generated material.

  1. Archive AThe clip's control sends its identity and lifecycle revision.
  2. Store transactionMark archived; remove every placement; retain source and edit context.
  3. New snapshotA is in the archive. Sequence and coverage reflect remaining placements.
  4. Restore AVisibility changes. No placement is created, so B stays unchanged.

  1. Intent enters at the clip.

    apps/web/src/ArtifactControls.tsx — search ArtifactControls and DeletionDisclosure.

    Archive/Restore are separate from Delete permanently. The component sends the intended artifact and revision, then refreshes the authoritative snapshot. Permanent deletion first shows a named disclosure; Cancel/Escape do not confirm it. The dialog's focus-return regression is tested too.

  2. The database owns the meaning.

    apps/server/src/studio/store.ts — search lifecycleChange, acceptDeletion and finishDeletion.

    lifecycleChange removes placements on archive but never recreates them on restore. Lifecycle state is additive: old generation JSON is not rewritten. Delete acceptance checks dependencies and removes access/placements atomically; final “deleted” requires completed purge evidence.

  3. Deletion adds durable filesystem work.

    apps/server/src/studio/lifecycle-manager.ts — search createLifecycleManager.

    Unlike Archive, Delete needs a bound inventory, exact consent, durable idempotency and resumable work. The manager coordinates store transitions with runArtifactPurge, which verifies file identity/checkpoints. Failure remains visibly deleting; retained history/thumbnail are not a recovery copy of full media.

Why not hide the item and delete its video file?

An artifact can also have raw PNG frames, conditioning/replay copies, workspace copies and assembled render caches. “Deleted” would be misleading if those managed full-media representations remained recoverable. The purge tests and actual slice-8 filesystem audit check known managed copies while protecting independent successors and text history. Downloads, backups, unknown external copies and secure disk erasure are outside that promise.

What did the recorded evidence actually establish?

Slice 8 has an 11-stage real CPU/HTTP proof, an independent post-purge file/hash audit, and isolated browser Archive/Restore/Cancel/Escape observations. Deleted media GET/HEAD/range was unavailable while the small thumbnail remained available. Permanent acceptance was tested through actual HTTP on disposable data, not a destructive browser click. No production media was archived/deleted; no new GPU-quality or human-listening claim follows.

The 160-criterion evidence index keeps fixtures, native execution, browser observation and remaining gates separate.
