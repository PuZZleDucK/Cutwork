# AI Music Video Maker — Product Requirements

**Working description, not a chosen product name.** A beginner describes a musical and visual idea in ordinary language; an agent handles specialist tool prompting, while the user inspects results, assembles a timeline, and exports a playable music video.

Approved by the learner on 20 October 2026 ("looking good"), after the requirements interview and review clarifications. This is a product definition, not an implementation plan or evidence that any generator works. Markdown is canonical; `prd.html` is its offline visual review companion. On 21 October 2026, during `4-spec`, the learner explicitly replaced the configurable 30 fps default with a globally fixed 24 fps rate for v1 after checking H3's native output. The learner also explicitly amended all beat-based generation presets to scale through 8, 4, 2, and 1 beats, chose a non-blocking warning above 15 seconds, and rejected a blanket four-second minimum on 21 October. The same review named Dundee as the deployment target, retained fully capable creative agents with project-specific working context, and confirmed Continue From End on each clip. The learner accepted the other technical proposals, including busy-media deletion protection and preserving archived-song arrangements. These amendments are approved; no second sign-off is required. Host-versus-tool dependency packaging was accepted with the technical spec on 21 October 2026; it is an implementation decision, not an added product feature.

## Changes to the Approved Scope

The initial scope was approved on 19 October 2026. The following interview additions and refinements were approved with this PRD on 20 October 2026 and have been reconciled into `scope.md` and `scope.html`. This section retains the change rationale so the expanded boundary remains visible rather than appearing to have been part of the original minimal sketch.

- **Multiple isolated projects are essential.** The proof still uses one short song and roughly three clips, but the product is not restricted to making one video ever. Tool installations are shared; project music, clips, sequence, archive, and history are separate.
- **Each generated song keeps its own arrangement within its project.** A successfully generated new song becomes selected automatically with no clip placements; the older song becomes unselected but retains its saved arrangement. Existing clips remain in the project's shared clip library, and the user can switch back later. This adds saved per-song edits, not automatic transfer, retiming, or regeneration of clips for a replacement soundtrack.
- **Agent setup comes before the generation-tool setup steps.** Choose Codex with the requested Sol 6.1 model or Claude with the requested Opus 5.5 model. The product interacts with the selected agent through its terminal interface, and a shared navbar status indicator identifies the selected provider. Other providers and user-selectable models are deferred; exact model identifiers, availability, and integration feasibility remain unverified.
- **Setup is a shared extension of the navbar, not project content.** Switching projects does not affect installation or monitoring; both continue across page reloads. All tool indicators are visible from the outset, disabled until installed. Keep every setup panel visible as a group until all required tools and provider sign-in are ready; completed steps lose their hazard stripes without disappearing individually.
- **Generation continues across project switches and page reloads.** Returning to the originating project shows the existing attempt or its result, not a new generation. A successful clip is added to that project's library and sequence as usual, either when it completes or when the project is reopened, without duplicate additions.
- **Queued and running clips have library placeholders with cancellation.** Cancellation stops the work immediately, then offers Restart, Discard, or Restore parameters for editing. This adds actual generation-lifecycle control, not just hiding a progress indicator; interruption support must be verified for the selected tools.
- **A bounded generation history is now requested for the prototype.** Each generation exposes user inputs, the actual tool prompt/settings, and an output thumbnail. Permanently deleting its media preserves that generation record, thumbnail, and text logs, and adds a separate deletion event. This partially brings back the deferred creative-history feature, not workflow sharing, replay, or undo.
- **Revision and basic assembly are concrete:** archive/restore, permanent deletion, fresh generation, automatic placement at each clip's planned times, removal from the sequence, and timing/placement adjustments. Archiving a clip or confirming its permanent deletion also removes it from the project's timeline automatically, rather than leaving hidden or missing material in the edit or requiring a preliminary manual removal. Restoring an archived clip returns it to the clip library unplaced, without reinserting it or disturbing the current edit.
- **All beat-based generation presets share an adaptive duration rule.** Start with eight beats at 50 BPM or above, otherwise four; halve to two or one if the proposed duration would exceed 15 seconds. Stop reducing at one beat and warn if it is still over 15 seconds. This applies to initial selection, gap filling, Continue From End, and post-song presets. Ordinary suggestions start at the earliest unassigned beat and stop before the next assigned range, using at most this preset count rather than filling an arbitrarily long gap. An empty arrangement starts at 0.00. Basic beat analysis is required. These are defaults, not restrictions on manually entered ranges. Default Clip Timing gives threshold examples and exact behaviour.
- **Post-song generation can continue clip by clip.** Retain the full adaptive preset window at the music boundary where unassigned, then keep suggesting further adaptive windows after the song is fully assigned. The product must not stop at the song's end or allow only one overhanging clip. Add a non-blocking start-selector warning when the clip starts at or beyond the end of the audio, alongside the existing end-selector warning. Included post-song clips remain in preview/export, using silence or the dominant clip's enabled audio. This expands the earlier single-final-clip exception; it does not add pre-song intros, an effects editor, or a verified feature-length rendering guarantee. The demo remains short.
- **The visual-editor controls remain part of the requested prototype.** Waveform/beat markers, optional persistent visual style, and a clip-level continue-from-end action are essential. Continue-from-end selects the previous clip's last retained frame after any trimming as the next starting frame, starts the next clip immediately after the previous final displayed frame without beat snapping, and sets its end the adaptive preset beat count later. This makes frame-precise timing essential, even though fine trimming was previously the lowest-priority demo item. Continuation timing follows the previous clip's current edited end after moving or trimming, not its original generation end. The source image follows the trimmed ending as well: use the last retained frame, not the discarded original ending. The persistent visual style and each individual clip prompt are both passed to the video-generation agent, so the user need not repeat the overall style. The clip display exposes exact inclusive start/end frame numbers; increasing the start or decreasing the end trims the retained range. Trimming preserves the surviving frames' existing song times, leaving uncovered frames where content was removed unless another clip covers them. A separate placement change can move the retained clip earlier or later. Reusing a generated final frame is an explicit, narrow image-guidance exception; separate image generation and general-purpose image-guided editing remain deferred.
- **Use a globally fixed 24 fps frame rate.** Video timing, frame-number trimming, continuation, preview, and export use the same exact 24 fps grid across all projects. No frame-rate selector, per-project rate change, or rate conversion is included in v1. This explicit 21 October amendment supersedes the earlier configurable 30 fps default. A fixed rate does not prove that the generator can produce every requested frame count or that every beat lands on a frame boundary; those constraints and timing conversion still need specification.
- **Duration guidance is advisory, not a blanket model-range restriction.** Requests longer than 15 seconds show a warning suggesting multiple generations, without blocking, shortening, or automatically splitting the request. Exactly 15 seconds does not trigger it. There is no blanket four-second minimum or automatic padding/trim solely to enforce that minimum. Actual tool constraints and failures still require truthful reporting; this does not guarantee every duration works.
- **Coverage and black gaps are part of the core workflow.** Show how much of the music has video coverage, highlight uncovered intervals, and render those intervals black in both preview and export. Full coverage is not required to export.
- **Overlapping clips use a single visible winner.** The second/newly placed clip is dominant by default. A control swaps which clip is in front by sending it behind the other, without changing either clip's timing or source media. Only the dominant clip can supply clip audio: use its audio when enabled, otherwise the original song (or silence after the song ends). Hidden clips contribute no audio. This is not blending, a transition, or permission for a full multitrack editor.
- **Song audio conditions video generation by default.** Supply the project's song audio to the video generator for every clip on the default path, independently of which soundtrack source the user later chooses for assembly. The learner reports that H3 generally reproduces supplied music in its output and may mix in diegetic sound; this capability and its fidelity/alignment have not been verified here.
- **Clip audio is an optional soundtrack replacement, not an added layer.** The original song is the default soundtrack. Choosing a clip's own mixed audio replaces the original song for that clip's interval, because the clip is expected to already contain the supplied music plus any generated sounds. If a clip has moved from its initial timeline position, mark its clip-audio option with a non-blocking warning; intentional mismatches remain allowed. This does not add a separate foley generator.
- **Provider selection can be reopened, not permanently locked.** Clicking the agent's navbar status indicator brings back its Codex/Claude configuration panel. Selecting the alternative returns the panel to a status indicator showing the new provider. Existing queued/running requests keep their originally assigned agent; only newly submitted requests use the new selection. This is the prototype example of the future status-to-configuration pattern, not a general configuration editor for every tool.
- **Timing has linked editable units.** Show beats, seconds, and frames for each relevant timing value; editing any representation updates the others. Beats and seconds accept arbitrary fractional precision, not a fixed five-digit limit; the frame field identifies the whole frame containing the most recently entered beat/time instant. Preserve the entered timing intent separately from its frame-aligned realisation. Consistent conversion and boundary handling still require technical verification.
- **Keep original generated frames as well as encoded video.** Preserve frames before lossy video encoding, or in a lossless equivalent, so starting/ending reference images do not acquire video-encoding degradation. This adds storage and media-lifecycle responsibilities; the reported H3 output behaviour still needs verification.
- **Seeds are part of generation provenance.** Fresh creative generation uses a new recorded seed for each seed-controlled tool call. Retrying a failed tool call or restarting a cancelled generation reuses its seed; reusing parameters for a variation chooses and records a new seed. Varying seeds supports exploration of near-miss results, while retaining seeds supports reproducibility. This is not a guarantee of bit-identical results.
- **Setup recovery includes an explicitly authorised autonomous debugging agent.** This is more than a retry button and adds a meaningful implementation and permissions burden.

These refinements increase the build beyond the original minimal assembly sketch. The curriculum's nominal 2–4 active-hour target is not a credible established estimate. The product behaviour is approved, while tool feasibility remains unverified; a short demonstration does not make the implementation small.

## The Core Journey

1. Open the interface on the supported setup. Find Projects and Config navigation and a project selector. All tools have compact navbar indicators from the outset, disabled until installed. The shared setup strip retains every panel until all tools are ready.
2. On first use, begin with agent setup: select Codex or Claude, using its fixed prototype model, before the music/video/analysis setup steps. Then start the required tool installation individually or with Install all. See progress and failures even after switching projects or refreshing the page. Retry an installation or explicitly authorise a debugging agent when needed. As each setup succeeds, clear its hazard stripes and enable its existing navbar indicator, retaining its panel. Clear the complete setup strip together only when every tool is ready; the agent indicator identifies the selected provider.
3. Create or select a project. Its creative material stays separate from other projects; already-installed tools are reused.
4. Enter a music description and optional lyrics, then click Generate. The agent translates the inputs into the generator's prompt/settings and runs it without an intermediate approval of that translation.
5. On successful music generation, show the new song selected with no clip placements and the previous song unselected. Listen to the new song and inspect its generation record. If dissatisfied, make a new attempt with changed inputs rather than undoing or editing the completed generation. The user can select an older song and return to its saved arrangement. Existing clips stay in the project library but are not automatically placed on the new song.
6. Use the globally fixed 24 fps grid to describe and generate accompanying video clips, with the selected song's audio supplied to the video generator by default. For an empty arrangement the first proposal starts at 0.00 and uses the adaptive preset beat count (8, 4, 2, or 1). Subsequent proposals start at the earliest unassigned beat, use at most that count, and stop before an assigned range. Keep the full preset window at the music boundary where unassigned, then continue with further free presets after the song. Show a non-blocking warning above 15 seconds; do not impose a blanket four-second minimum. Each request captures its song and start/end times before generation so the correct audio context can be supplied. Each successful clip enters the project's library and is placed at those planned times in its originating song's arrangement, not whichever song or gap happens to be selected at completion.
7. Inspect the sequence and coverage indicator. Use the displayed exact start/end frame numbers to trim a clip's retained range. Adjust clip timings or placement, remove unwanted placements, or generate additional clips. Uncovered intervals are visibly marked.
8. Preview the assembled video with the original song by default. Optionally select a clip's mixed audio instead of the original song for its interval. Uncovered intervals show black frames with the original song continuing; they are not silently filled, stretched, or looped.
9. Export a real video file, including black frames wherever coverage is missing and retaining all included post-song clips, including further clip-by-clip continuation. Play that file independently in VLC as the end-to-end proof.

### Confirmed Editor Controls

Waveform/beat visualisation, optional persistent visual style, and continue-from-end are confirmed as essential prototype capabilities. The learner has now identified a concrete need for fine timing: a continuation must start on the next video frame even when that position falls between beats. Frame-precise timing therefore cannot be deferred merely because fine trimming is absent from the demo. Trimming keeps the surviving frames at their existing song times; a separate placement edit moves the retained clip. Removing leading frames therefore leaves a gap by default rather than automatically pulling the retained footage earlier.

Continue-from-end now has explicit starting-frame and timing defaults, defined under its own behaviour heading. It prepares inputs for the existing generation flow, not an automatic chain of generations. For a moved or trimmed predecessor, continuation timing follows its current edited end: start there and end the adaptive preset beat count later. After trimming, the starting image is the trimmed clip's last retained frame. Continuation's frame and timing choices are settled. Persistent visual style is also settled: give the agent both the retained overall style and the individual clip prompt. Frame-number trimming preserves existing song-time alignment by default; the user can separately reposition the trimmed clip. A last-frame reference does not establish a seamless visual join or prescribe prompt inheritance.

Basic timing/placement, ordinary gap-aware defaults using the adaptive 8/4/2/1-beat count, beat analysis, fresh generation, and per-clip soundtrack selection remain confirmed. The explicit continuation action instead uses its predecessor's next-frame boundary with the same adaptive preset duration. Additional audio editing, manual beat-grid editing, and general-purpose image-guided workflows remain deferred. ## Features and Behavior

### Projects and Shared Tools

Users can make more than one project and return to each project's own material. The only shared working resources identified by the learner are the underlying tools; creative content is not pooled between projects. Shared configuration is for those tools/provider connections, not shared creative defaults.

Within a project, generated songs have separate saved arrangements, while its clip library remains shared among those songs. Switching songs is distinct from switching projects; neither action copies or merges another song's placements. Song Selection and Saved Arrangements defines that behaviour.

Switching projects or reloading the page must not stop an in-progress generation. The attempt remains associated with the project where it was submitted, regardless of the project currently displayed. A successful clip is added to its originating project's library and timeline under the normal placement-at-requested-times rule, either on completion or when that project is reopened. The user does not need to resubmit the request or manually recover the output. Reopening before completion shows the existing attempt still in progress; reopening after completion shows its outcome. Neither action starts another attempt or adds the same completed clip twice.

This requirement covers leaving or reloading the interface while generation continues, unless the user explicitly cancels it. Queued requests and cancelled placeholders also retain their state on return; reopening must not restart cancelled work. It does not promise uninterrupted generation through a tool, application-service, or machine shutdown, or require simultaneous GPU jobs. Installation and its monitoring also continue independently of project selection and page reloads, as defined in Tool Setup and Failure Recovery.

Acceptance criteria:

- **P1:** Create projects A and B; music, clips, sequence, archive, and generation history in A do not appear in or overwrite B.
- **P2:** Switching back to A restores A's project material. Reopening a saved project preserves completed work and shows the current state or outcome of a generation that continued while the user was away.
- **P3:** Switching or creating projects does not require reinstalling tools that are already ready.
- **P4:** The project selector can show coverage without labelling it an overall quality score or a completed export.
- **P5:** Start a clip generation in A, switch to B, and let it complete: the result belongs to A, not B. On returning to A, its clip library, timeline, generation history, and coverage reflect the successful addition without another Generate action.
- **P6:** Reload the page during generation and reopen its project: the same attempt continues, with its original inputs intact. If it is still running, show that state rather than an empty form implying no submitted work or a fresh duplicate attempt.
- **P7:** If generation completes while the project is not displayed, its outcome is visible on reopening. A successful clip appears once under the normal library/planned-placement behaviour; repeated reloads or reopening do not duplicate the attempt or place its result again. A failed attempt instead shows the established failure details and retry options, with no fabricated clip.

### Frontier Agent Setup and Selection

The first shared setup step is the frontier agent, before music generation, ComfyUI/H3, and audio analysis setup. Offer a choice between **Codex** and **Claude**. The product handles interaction with the selected agent through its terminal interface; ordinary creative inputs still belong in the product UI, not a manually constructed terminal prompt for each generation.

**Creative agent authority:** normal project agents retain their ordinary tools and capabilities, including research, relevant history, shell/scripts and score editing. Supply project/tool knowledge and useful capture helpers; do not impose a product sandbox, read-only mode, disabled-tool list or mandatory JSON response. Start project workers in a known project-specific runtime workspace, sharing artifacts with that project's workers rather than a global creative directory. This organises context, not filesystem access. Confirmed shared-tool Debug retains its separate tool-directory launch context.

Use fixed requested model pairings for the prototype: **Codex → Sol 6.1** and **Claude → Opus 5.5**. These are the learner's requested labels, not verified provider-facing identifiers or claims of availability. Additional providers and a user-facing model selector are later advanced features. Do not silently substitute another provider or model if a requested pairing proves unavailable; resolve that with the learner during technical investigation.

Selection and setup are shared across projects. **Provider selection is reversible through the navbar.** Click the agent's status indicator to bring back its selector/configuration panel with the current choice shown. Select the alternative provider and return that panel to the status area, now displaying the new configuration. Do not lock the first selection forever or require rebuilding projects to change it. Existing installation/authentication checks still apply; a selection change is not evidence that the alternative is ready. This is the explicit prototype configuration interaction for the agent, while broader tool configuration remains later.

**A provider change applies only to new requests.** Each submitted request retains the agent provider selected when it was accepted, including while waiting in the queue. Already queued or running requests continue with that original agent without changes caused by the switch; do not migrate, cancel, restart, or rewrite them. New requests submitted after the change use the newly selected provider, subject to its existing readiness checks. Switching again follows the same rule. This is a routing rule, not a guarantee that work cannot fail independently or that requests run concurrently.

The agent indicator is present from the outset and explicitly names the selected provider. Enable it after installation, but retain the configuration panel with the other setup steps until the entire toolchain is ready. The choice or installation alone is not proof the agent is authenticated or usable. If the installed agent is not signed in, show an **error status in the navbar**, with a **hover tooltip containing details of how to sign in** to that selected provider. This error must not be presented as ordinary Idle / not running or as successful agent readiness. After sign-in has been verified, return to the normal activity/queue display. Exact provider-specific sign-in instructions and the readiness-check mechanism belong in `4-spec`; this requirement does not add an embedded login wizard or credential-entry form.

Both existing requests keep Codex and continue to their normal outcome without changes caused by the switch, including the queued request when it starts. ### Music and Video Generation

Music inputs are a creative description and optional lyrics. Video generation accepts a clip description and receives the selected song's audio as input by default. The user does not have to manually supply the audio again for each clip. Passing song audio to the generator is independent of the later per-clip choice of which soundtrack to use in the assembled video. The agent handles specialist prompt translation and invokes the relevant tool. The user does not need to approve that intermediate translation before every generation.

Optional persistent visual style and a clip-library continue-from-end action are required for the prototype. Continue From End defines the latter's frame reference and timing. Persistent Visual Style defines how the retained general style accompanies each individual clip prompt to the agent; this is not automatic copying of a previous clip's individual prompt. Continuation after moving or trimming is settled: follow the predecessor's current edited end and select its last retained frame.

Submitted inputs define that attempt: they are not edited midway through it. Changes for a different result create a new attempt. The user can cancel queued or in-progress generation; the clip-library flow is defined below.

**Assign the clip's placement when the generation request is submitted, not when it finishes.** Record its originating project, song, and planned start/end times before queuing or invoking H3. These times determine the requested song-audio context as well as the eventual initial timeline placement. They may come from the ordinary gap-aware default, the explicit continue-from-end action, or the user's edits. Once accepted, the request reserves that range for subsequent suggestions; the next form values are not the submitted attempt's values.

On success, place the clip at those recorded times in its originating song's arrangement. A request for an earlier gap fills that planned gap; it is not appended after later clips, placed at the next currently free beat, or positioned according to completion order. A changed form, song selection, or newly available gap does not rewrite its planned interval. The user may adjust the completed placement afterward under the existing editing rules. This refines the earlier "append" wording into automatic placement at the requested interval.

Generation continues when the user switches projects or reloads the page. Completion and failure remain attached to the originating project, following Projects and Shared Tools; neither navigation nor reopening is a new generation request.

For queued or in-progress video generation, show a placeholder in the clip library rather than waiting until a finished clip exists. Its status distinguishes queued from running, and it offers Cancel. Cancellation must immediately prevent a queued attempt from starting or stop an active attempt, not merely hide its placeholder while generation continues. After the attempt has stopped, retain a cancelled placeholder with three actions:

1. **Restart:** start another attempt using the cancelled attempt's submitted creative inputs and settings, including its timing range and the same recorded seed, rather than the generation form's current defaults. This recovers an unfinished generation, not a creative variation or resumption of partial progress. Retain both attempt records.
2. **Discard:** remove the cancelled placeholder without starting another attempt.
3. **Restore parameters:** populate the generation UI with that attempt's parameters for editing, and discard its placeholder. Restoring does not generate automatically; the user edits and explicitly starts a new generation.

Discarding a placeholder does not erase the attempt's retained history; optional history removal remains deferred. Cancellation is distinct from failure and from deleting a completed artifact. A queued, running, or cancelled placeholder is not playable media and does not enter the timeline or count toward coverage.

Immediate stopping is the requested behaviour, not an established tool capability. If stopping is not yet confirmed, the UI must show that cancellation is pending rather than falsely claiming the work has stopped. Verify actual interruption support in `4-spec`; if a selected tool cannot meet the requirement, return to the product decision rather than silently substituting "let it finish and hide the result."

Acceptance criteria:

- **G1:** Generate proceeds from user inputs to agent/tool execution without a second prompt-approval step.
- **G2:** A completed music output can be heard; a completed video output can be inspected. Each is associated with its generation record.
- **G3:** A failed attempt has a visible failure indicator and expandable details. It is not represented as a successful playable artifact.
- **G4:** Retry repeats the failed tool request with its same prompt/settings and recorded seed. Restore/reuse parameters repopulates the editable generation fields so the user can change them before starting a new attempt, for example shortening a video request after a memory failure; that new generation receives a new recorded seed rather than copying the failed attempt's seed.
- **G5:** Each successful new video generation enters the project's library and is automatically placed at its request's recorded start/end times in the originating song's arrangement, including an earlier gap. Changing the selected song while generation runs does not redirect that placement. The user can remove the completed placement or adjust it afterward. This automatic placement does not apply to restoring an archived clip, which returns to the library unplaced.
- **G6:** Refining a result produces a fresh generation; it does not rewrite the original attempt's historical inputs or claim to undo the generated media.
- **G7:** The default video-generation request includes song audio as an input even when the assembled video will use the original song rather than the generated clip's audio. The requested audio context corresponds to the song and start/end times captured for that attempt, not later form values. The actual media input is inspectable in the generation record. Default Clip Timing defines ordinary suggestions and Continue From End defines explicit continuation inputs; the delivery mechanism, such as an excerpt versus a full track with timing instructions, belongs in the spec. - **G10:** Once cancelled, its placeholder offers Restart, Discard, and Restore parameters. Navigating away and returning preserves this state and does not restart the attempt automatically.
- **G11:** Restart uses the cancelled attempt's submitted creative inputs/settings, timing, and same recorded seed, creating another attempt rather than editing the historical attempt, resuming partial work, or requesting a new-seed variation. ### Generation Seeds and Variations

Every fresh creative generation, including a requested variation, selects and records a new random seed for each seed-controlled generation tool used. Recovery through failed-call Retry or cancelled-generation Restart instead preserves the existing seed, even though it creates another attempt record. The history must expose the actual seed supplied or resolved by the tool, associated with that tool call, alongside the user inputs and agent-produced prompt/settings. Do not merely record an unresolved "random" sentinel as if it were the actual seed. Supported seed controls and how the actual seed is obtained still need verification for each integration.

**Failed-call Retry preserves the seed.** It retries the failed tool call with the same recorded seed and parameters, rather than turning failure recovery into an unrequested variation. If failure occurred before any tool invocation, history must continue to distinguish assigned/requested inputs from inputs actually sent; do not fabricate a call.

**Cancelled-generation Restart also preserves the seed.** Restart is the action offered for a cancelled attempt, not for a completed result. It uses that attempt's same recorded seed and submitted generation parameters because the requested generation did not finish. This is a new execution attempt from the beginning, not a continuation from an intermediate generation checkpoint. Preserve the cancelled record and associate the restarted attempt with the reused seed. For a request cancelled before any tool call, distinguish its assigned seed from evidence of an invocation; do not fabricate a call or output.

**Reuse/restore parameters prepares a variation.** Copy the editable creative parameters, but choose and record a new seed when the user submits the new generation. Restoring the form alone starts no work. Keep the earlier attempt's seed/history unchanged so the two results can be compared. No manual seed-entry control is added by this requirement.

**Why these choices differ:** a completed result may be close to the desired outcome without quite succeeding. Varying the seed lets the user explore another result without having to rewrite otherwise useful creative parameters. Recording the seed alongside the actual inputs and settings supports reproducibility and understanding how a particular result was made. Retry and Restart are recovery paths for unfinished work, not requests for creative variation.

A seed records one input to generation, not a guarantee of identical output across tool/model versions, settings, hardware, or other sources of variation. Retain the distinction between supporting reproducibility through provenance and promising bit-identical reproduction. This rationale does not add a manual seed editor, completed-output replay action, or automatic variation batch to the prototype.

Acceptance criteria:

- **SD1:** A fresh creative music or video generation records the actual seed for each seed-controlled tool call with its prompt/settings. Fresh generations and variations use new seeds rather than silently inheriting the last attempt's seed; recovery via Retry or Restart follows the explicit same-seed rules instead.
- **SD2:** Retry a failed tool call with recorded seed S: the retry supplies S again with the same tool parameters, and its record identifies that seed. Do not substitute a newly randomised seed on this recovery path.
- **SD3:** Reuse/restore an earlier generation's parameters and then submit a new generation: use and record a new seed, not that earlier generation's seed, while retaining the requested non-seed parameters and any user edits. Opening/restoring the form is not itself a generation.
- **SD4:** Earlier attempt records keep their original seeds after retries, restarts, variations, later style changes, or deletion of full output media, under the existing provenance-retention rules.
- **SD5:** Cancel a generation with recorded seed S, then choose Restart: the restarted generation supplies and records S again with the original generation parameters. The cancelled attempt remains separately identifiable in history. Restarting an unfinished generation does not select a new seed merely because a new execution attempt is created; choosing Restore parameters and then Generate still follows the new-seed variation rule.

### Linked Timing Units

Show timing in **beats, seconds, and frames**, and allow the user to edit any of those representations. Updating one updates the others using the video's frame rate and the song's timing analysis. Beats and seconds describe the requested timing position; the integer frame field identifies the frame containing that instant. These are linked representations, not independent settings, but an instant inside a frame is not identical to that frame's start or end boundary.

**Beats and seconds accept arbitrary fractional precision, not five decimal places or five significant digits.** For example, the user can enter `12.3456789` seconds or beat `1.3333333`, approximately one-third of the way between beats 1 and 2. Preserve the entered value rather than overwriting it with a rounded frame timestamp merely because the linked frame field updates. The most recently edited beat or seconds value supplies the timing intent; selecting a whole frame directly instead updates the beat/time fields to the corresponding frame-boundary value under the control's labelled start/end convention. Extra decimal digits do not imply matching beat-detection accuracy, fractional video frames, or infinitely accurate media timing.

Interpret the requested frame quantisation as **the frame containing the entered instant**, not ordinary rounding to whichever frame-start timestamp is nearest. For an illustrative sequence starting at zero with one-based frame labels at 24 fps, `12.3456789` seconds falls inside frame 297, whose display interval starts at `296/24` seconds and ends at `297/24` seconds. The requested seconds value remains `12.3456789`; playable cut boundaries remain on the frame grid. This is a numerical example, not evidence of generator support.

Preserve context: source-frame trim bounds and timeline/song positions are not interchangeable. Label the units and their context, retaining the existing one-based inclusive source-frame convention and the established trim-versus-move behaviour. Specify exact-boundary ownership and the inclusive-end/time-boundary conversion in the spec so the containing-frame rule cannot introduce an off-by-one trim or a blank frame. Clearly distinguish entered timing intent from realised media boundaries; request-time audio conditioning and planned placement must use the same consistent conversion, not independently round into different intervals.

Acceptance criteria:

- **U1:** For an editable timing position or range, display linked beats, seconds, and frame values with clear labels and allow editing through each unit representation. Distinguish requested timing from the frame-aligned media boundary where they differ.
- **U2:** Edit one representation: update the others consistently using the current song timing and established frame rate. A beat/time edit retains the entered precision while updating the containing frame; a direct frame edit updates the corresponding beat/time position. Merely switching the displayed unit does not move or trim the clip, and repeated conversions must not progressively shift the selected content.
- **U3:** Preserve the distinction between selecting retained source frames and moving footage on the song timeline. A different unit representation does not silently turn one operation into the other.
- **U4:** Accept fractional seconds such as `12.3456789` and fractional beats such as `1.3333333` without imposing the previously mentioned five-digit limit or snapping them to whole beats. Beat `1.3333333` denotes approximately one-third of the interval from beat 1 to beat 2. The entered timing intent survives linked-field updates and reopening the saved edit.
- **U5:** Frame values remain whole numbers. In the zero-origin, one-based 24 fps example, entering `12.3456789` seconds selects containing frame 297 without replacing the seconds input with `296/24` or `297/24`. A later beat/time edit recalculates the containing frame from that newly edited value, not from a previously quantised value. Realised media still uses whole frames and the documented start/end boundary convention.

### Frame-Based Trimming and Locked Frame Rate

Each clip display shows the exact **first and last included source frame numbers**. Use one-based, inclusive labels: an 80-frame source initially shows **Start frame 1 / End frame 80**. The user can increase the start number to remove leading frames or decrease the end number to remove trailing frames. These identify retained source content, not beat numbers or a replacement for the separate timeline position.

For example, changing 1–80 to 6–75 retains 70 frames: remove source frames 1–5 and 76–80. The learner's example of ten frames per beat would make an untrimmed eight-beat clip 80 frames, but ten frames per beat is illustrative, not a universal conversion or chosen frame rate. The exact control styling is a spec/design detail; whole-frame numerical precision is required.

**Use exactly 24 fps globally for v1.** All projects, generated clips, timing controls, source-frame trimming, continuation, preview, and export use this common frame grid from the outset. Show the rate as information, not an editable selector. There is no per-project rate choice, later rate change, or frame-rate conversion. Record and verify the actual media rate instead of merely assuming it matches the policy. The learner explicitly chose this on 21 October 2026 after H3 investigation, replacing the earlier configurable 30 fps default. This simplifies frame/time mapping without asserting that all musical beats coincide with frames or that arbitrary requested frame counts are native generator outputs.

A fixed frame rate does not make every musical beat a frame boundary. For example, at 24 fps and steady 100 BPM, one beat lasts 14.4 frames and eight beats last 115.2 frames. A playable frame-count range must use whole frames, so the spec must define the mapping and any timing error explicitly and consistently. The eight-beat request remains the musical intention; do not silently claim fractional frames or exact beat/frame coincidence. The generator's ability to deliver a requested frame count is also unverified.

**Trimming does not automatically move the retained content.** Keep each surviving source frame at its existing time against the song. Removing the first five frames leaves five uncovered frame positions at the beginning unless another included clip covers them. Do not pull the retained content earlier, close the gap automatically, or shift neighbouring clips. Existing gap marking, coverage, and black-frame playback/export rules apply.

**Moving remains a separate, already-required control.** The user may move the trimmed clip earlier to cover that gap or place it elsewhere when the changed timing is intentional. Moving changes the retained content's song-time alignment, not the selected source-frame bounds. Apply the existing moved-clip audio warning when that movement shifts it from its initial alignment; trimming alone, while preserving the surviving frames' song times, is not such a move.

Acceptance criteria:

- **FT4:** The chosen retained range is reflected in the displayed clip, preview, and export. ### Continue From End

The next-frame boundary means immediately after the previous final displayed frame, without an extra empty frame or a snap to the next musical beat. The adaptive 8-, 4-, 2-, or 1-beat duration is measured from that precise start, retaining its offset from the beat grid. The learner explicitly applied the shared duration rule to continuation on 21 October. This is a deliberate continuation action, not the ordinary earliest-unassigned-gap suggestion. Frame-precise timing must remain usable in the prototype. - **R1:** Use the Continue From End control on an available generated clip's own card, without selecting a predecessor elsewhere: the next generation's starting-frame input selects its last retained frame after any trimming. Use the matching preserved pre-encoding frame under Raw Frame Preservation, not a generic thumbnail, newly generated image, or lossy-video extraction. The continuation action does not alter the previous clip.
- **R2:** The start field targets the immediately following frame boundary at the predecessor's current timeline end, including after moving or trimming it, even when that boundary lies between beats. Do not snap it to a beat, substitute the earliest free gap, or add an extra empty frame after the predecessor's end boundary.
- **R3:** The end field is the shared adaptive preset beat count after that precise start. At steady 15 BPM it selects two beats (eight seconds); at steady 120 BPM it selects eight beats (four seconds). For example, a 99-frame clip starting at 0 at 24 fps occupies 0–4.125 seconds; its last frame starts at 98/24 seconds. Its continuation starts at 4.125 and ends at 8.125, not at beat-aligned 4.5–8.5. These illustrative timings use the selected 24 fps rate, but do not establish model frame-count limits. They land exactly on frame boundaries; for other tempos, the spec must define the whole-frame mapping described in Frame-Based Trimming and Locked Frame Rate.
- **R4:** The generation form preserves these frame-level timing values rather than rounding them to whole beats. Submitting the request captures that same start/end interval for song-audio conditioning and planned output placement, using the existing generation/history rules. Preparing inputs alone does not queue work or count as coverage.
- **R5:** The over-15-second duration warning, existing start/end warnings, and post-song soundtrack rules also apply to a continuation that crosses or follows the music's end. Reusing the final frame does not add transitions, crossfades, or a guarantee of seamless motion.
- **R6:** Move or trim the predecessor before choosing continue-from-end: derive the new request's start and end from that clip's edited timeline end, not its original generation range. At steady 120 BPM, an edited end at 10.125 seconds proposes 10.125–14.125, even if the original generation ended at 4.125. When the predecessor is trimmed, its last retained frame is also selected as the new starting image, as defined in R1.

This is a bounded exception to deferred image-guided workflows: an existing generated frame becomes the next clip's input. No separate image-generation tool is required. Supported image-plus-song-audio conditioning, frame accuracy, and achievable continuity remain technical verification tasks, not demonstrated capabilities.

### Song Selection and Saved Arrangements

When the user explicitly selects a different song, restore its original user-entered music description and optional lyrics in the music form, including empty lyrics. Do not substitute the agent-transformed prompt or lyric sheet. Keep the current project visual style unchanged. Reselecting the already-selected song does not discard edits. This does not modify immutable generation history or existing requests.

A project can retain multiple generated songs and let the user select which one to work on. **Each song keeps its own saved clip arrangement.** Selecting a different song does not carry over or retime clips from the previously selected song. The learner considers those clips generally unsuitable for a newly generated track; keep them available in the same project's clip library rather than automatically placing, archiving, deleting, or regenerating them.

The previous song retains its clip placements, timings, dominance order, and soundtrack choices. Switching back later, including after reopening the project, returns to that song and its saved arrangement. Work on the other song must not overwrite it. This is selection between retained edits, not undo, a new project, or a copy of the previous edit onto new music. Explicit artifact archive/delete actions still have their established effects; switching back does not undo those actions or recover deleted media.

A song with no arrangement yet starts with no placed clips, even if the project library already contains clips made for other songs. Its coverage is therefore 0% while its duration is known, and existing black-frame rules apply. A previously edited song instead shows its existing arrangement. Beat timing, coverage, the original-song soundtrack, preview, and export refer to the selected song and its arrangement, not a mixture of different songs' edits.

Keep video-generation requests tied to the song whose audio and timing were submitted. A later song selection does not rewrite the attempt or its provenance; on success, the clip is placed in the originating song's arrangement at the start/end times captured when requested. This extends the existing originating-project rule to the saved song arrangement, rather than placing a delayed result on whichever song is now selected.

**Successful music generation automatically selects the new song in its project.** Show its empty arrangement, with no clips placed yet, and mark the previously selected song unselected without clearing its saved edit. Selection changes on successful completion, not merely on submission of a request or a failed/cancelled attempt. This is a completion action, not a rule to always select the newest song: after the user manually switches back to an older song, reopening or refreshing must not force the newer song to become selected again.

Acceptance criteria:

- **M1:** Arrange clips for song A, then select a different song B that has not been edited: B has no clip placements, while the existing clips remain in the project's library. A's arrangement is retained rather than transferred, cleared, or automatically retimed to B.
- **M2:** After working on B, select A again: its saved placements, timings, dominance order, and soundtrack choices return. Returning to B likewise shows B's saved edit. - **M3:** A newly selected, unedited song B with known duration has 0% coverage despite clips being present in the shared library. Its preview/export follow the existing black-frame and original-song rules. Selecting an already-edited song instead uses that song's existing coverage and arrangement.

- **M5:** Start a clip request for song A, then select B before completion: the resulting clip joins the project library and A's arrangement, not B's. Returning to A shows the completed addition without resubmission or duplicate placement.

- **M7:** After B was automatically selected on completion, manually select A and refresh or reopen the project: A remains selected with its saved arrangement. Merely reopening does not repeat B's earlier completion action or force selection back to the newest song.

### Default Clip Timing

**Use one adaptive beat-count rule for every beat-based generation preset**, including the initial selection, filling a gap, Continue From End, and further post-song clips. The learner explicitly extended the rule to all these paths on 21 October 2026.

Start with **eight beats at 50 BPM or above**, otherwise **four beats**. If the proposed duration would exceed 15 seconds, halve the preset count along 8 → 4 → 2 → 1 as needed. Stop at one beat even if its duration exceeds 15 seconds; show the duration warning rather than inventing a smaller fractional-beat preset. The preset is a suggestion, not a cap on manually entered ranges.

For steady positive BPM, this gives these exact boundaries:

- **50 BPM and above: 8 beats.** At 50 BPM the duration is 9.6 seconds.
- **16 BPM up to, but not including, 50: 4 beats.** At 16 BPM the duration is exactly 15 seconds; at 40 BPM it is six seconds.
- **8 BPM up to, but not including, 16: 2 beats.** At 8 BPM the duration is exactly 15 seconds; at 15 BPM it is eight seconds.
- **Below 8 BPM: 1 beat.** At 4 BPM the duration is exactly 15 seconds. Below 4 BPM, one beat exceeds 15 seconds and retains the non-blocking warning.

The 16 and 8 BPM thresholds follow from halving when a duration is **strictly over** 15 seconds, not at exactly 15. For irregular timing, the spec must use the same beat-to-time mapping as the timing controls when evaluating the proposed interval; the steady-BPM examples are not permission to invent a constant-tempo grid. Missing/invalid analysis is not an extremely slow positive BPM value.

Ordinary suggestions use the earliest free gap. Continue From End instead retains its explicit predecessor-based frame boundary, applies this same adaptive duration from there, and keeps its off-beat offset. Do not substitute the earliest gap for a continuation start or snap that start to a beat.

For an empty arrangement, start the first proposed clip at **0.00** and use the **adaptive preset beat count**. Then suggest **up to that many consecutive unassigned beats beginning at the earliest unassigned beat**, stopping before the next assigned range. A longer free gap does not override the duration rule: propose one preset-sized portion and leave the remainder unassigned for later user-requested generations. This fills earlier gaps rather than always appending beyond the last clip. For an eight-beat preset with no gaps or other assigned ranges ahead, the sequence is beats 1–8, then 9–16, then 17–24, and so on. A two-beat preset instead advances 1–2, 3–4, 5–6. The user can prepare the next creative prompt while the preceding clip is generating. This is a default, not a fixed length required for every clip, and does not by itself require simultaneous GPU generations.

Changing a submitted clip's range does not change the adaptive count for later suggestions. In the following examples, assume a steady 60 BPM song, so the preset remains eight beats. For example, with beats 1–8 assigned, if the proposed 9–16 request is extended to 9–20 before Generate, the next proposal is **21–28** when that range is free. Preserve the submitted range rather than using its old suggested boundary. If beats 1–8 and 17–24 are assigned, suggest **9–16**. If beats 1–8 and 13–20 are assigned, suggest **9–12**: stop at the gap's end instead of overlapping 13–16 or combining disconnected free intervals into one request.

For suggestion purposes, included placements and queued/running requests occupy their assigned ranges. Do not propose the same reserved beats again merely because their generation has not finished. This is distinct from the coverage percentage, which still counts only included generated video, not placeholders. Clips merely present in the library do not occupy a timeline range. The no-overlap rule applies to ordinary automatically proposed gap ranges; it does not remove the user's ability to deliberately overlap clips and choose their dominance.

Describe the default using its actual adaptive count, up to 8, 4, 2, or 1 beats. Eight beats equals two bars only when there are four beats per bar; a different count, time signature, or shorter gap must not be silently labelled as two bars. The duration in seconds depends on the song's beat timing, rather than being hard-coded to eight seconds. Basic analysis of the track's beat timing is part of the prototype; the analysis tool and method belong in the spec, and manual beat-grid editing is not implied.

The end position is the boundary after the final included beat, also the start of the next range. For a steady 60 BPM example with beat 1 at 0.00:

- Beats 1–8 occupy 0.00–8.00 seconds; beat 9 starts at 8.00.
- Beats 9–16 occupy 8.00–16.00 seconds; beat 17 starts at 16.00.
- Beats 17–24 occupy 16.00–24.00 seconds.

These contiguous ranges avoid the off-by-one error of ending the first clip at the start of beat 8. They are examples for checking the default, not verified generator duration limits.

**Do not shorten the last default window merely to fit the song.** If fewer beats than the adaptive preset count remain and the following range is unassigned, still select the full preset duration, allowing the final clip to continue beyond the audio. The song's end is not an occupied clip boundary; another assigned range would still limit the suggestion. For example, an 18-second song at steady 60 BPM with no later assignment has a final default range of 16.00–24.00, not 16.00–18.00. Keeping that full clip gives six seconds of video after the music ends. The extra duration is based on the track's timing; it is not a claim that actual audible beats exist after the source ends. How to extend the timing grid in less regular material belongs in the spec.

When the selected end goes past the song's end, show an alert symbol beside the end-beat selector, with an explanation that the range extends beyond the available song audio. Like the moved-clip audio warning, it informs rather than prevents: it does not shorten the range, require another confirmation, or block generation, preview, or export solely for going past the song. Post-song sound follows the selected source as defined in Clip Audio.

**Continue suggesting clips after all song beats are assigned.** Apply the same gap-aware rule beyond the audio: where the following range is free, suggest the next full adaptive preset window, and continue doing so for further requests. Do not stop at full song coverage or after the first clip that outlasts the music. Preserve reserved ranges so a new suggestion does not overlap a pending post-song clip. The extended beat grid remains a timing reference, not a claim that audible song beats exist after the source ends.

When the selected start is **at or beyond the song's end**, show a matching alert beside the start selector explaining that this clip begins outside the available song audio. This is advisory, not a reason to clamp, disable, or require another confirmation for generation, preview, or export. The end warning still applies independently, so a wholly post-song interval can show both. Moving the start back inside the song clears the start warning without clearing an end warning that still applies.

The learner wants no music-end restriction on continuing a longer video, potentially far beyond the music-video segment. This is continued clip-by-clip work, not a promise of one arbitrarily long generation or verified feature-length performance. The selected generators' limits and export practicality still require investigation. A wholly post-song request has no original song samples at that interval; the spec must verify a suitable input treatment rather than silently looping the song to supply audio.

**Duration advisory, not a hard cap.** When the requested generation duration (end minus start) is greater than 15 seconds, show a warning marker with a readable hint to split the interval into multiple generations. Exactly 15 seconds does not trigger this advisory. Preserve the chosen range and keep Generate available; do not clamp, stretch, automatically split, or require an extra confirmation solely for exceeding 15 seconds. The warning applies to manual ranges and presets, including a one-beat preset below 4 BPM. Update it independently of the music-end and moved-clip warnings. Allowing an attempt is not a promise the generator or available VRAM will support it; genuine failures use existing recovery.

**No blanket four-second minimum.** Do not reject a 1–2 second clip or automatically extend it to four seconds solely because of the published ordinary duration range. The learner reports successful short clips; actual positive-duration/frame-grid and generator requirements still need verification. This decision does not guarantee arbitrary exact frame counts, approve a minimum-padding/trim workaround, or add a separate single-frame image-generation mode. In particular, do not copy the personal wrapper's convenience duration guards into the new product as hidden policy.

Acceptance criteria:

- **B1:** With the selected song ready, no placements, and no queued/running clip requests for that song, the generation form proposes a first range beginning at 0.00 and spanning the adaptive preset count: 8, 4, 2, or 1 beats under the rule above. Clips merely in the project's library, including clips made for another song, do not advance this song's starting range.
- **B2:** In the steady 60 BPM example above, the first three proposed ranges are 0.00–8.00, 8.00–16.00, and 16.00–24.00. At steady 120 BPM with the same zero-aligned beat grid, they are 0.00–4.00, 4.00–8.00, and 8.00–12.00.

### Artifact Archive, Restore, and Delete

- **Remove from sequence:** stop using that clip placement in the video; this is a different action from managing the generated artifact itself.

For a clip already used in the video, the same archive action automatically removes its timeline placement or placements. Do not leave an archived clip contributing to the edit or require the user to remove it manually first.
- **Restore:** bring an archived clip back into the active clip library **unplaced**. Do not reinstate its old placement, append it elsewhere, or disturb clips that may now occupy its former location. The user must explicitly place it into the video again. Restoration recovers the artifact, not the previous edit.
- **Delete:** require confirmation before permanently removing the full generated media, with no recovery path for that media. The dialog identifies the artifact, warns that the media cannot be recovered, and explains that its generation record, thumbnail, and text logs remain and a deletion event will be added to history. Provide explicit Delete and Cancel actions; opening or cancelling the dialog deletes nothing. The interface must not describe this as erasing all traces of the generation. An optional "also delete from history" choice is deferred until after the prototype, not offered in this confirmation.

Restoring that song makes it selectable again without automatically selecting it. Deleting a song removes its arrangement but does not delete separate generated clips. ### Timeline and Music Coverage

Show the selected song's waveform and beat markers together with the included clips, their positions, and uncovered intervals across the music. The waveform and markers use the same timeline reference as the clip placements and timing fields; they are not merely an unrelated decorative waveform. Users can adjust basic timings/placement and generate more clips to fill gaps. This requirement does not by itself authorise a full multitrack editor, transitions, or every proposed fine-editing control.

The displayed timeline and its coverage belong to the selected song's saved arrangement. Other songs' placements remain saved but are not included in this timeline or its coverage calculation. A project-level coverage indicator reflects the selected song's arrangement rather than combining coverage from several songs.

**Overlaps are allowed, with only one clip visible at a time.** When a second clip is placed over an existing clip's time range, the second/newly placed clip is dominant by default. Provide a control to swap which clip is dominant by sending it behind the other. This is a change of visual priority, not a move to another time, a destructive trim, deletion, or replacement of the underlying artifact. Keep both placements; a clip obscured during an overlap can still be seen in its non-overlapped portions. Do not blend the two images or automatically introduce a transition.

Coverage is the percentage of the music's duration with at least one included clip covering it. Count each covered instant once, regardless of overlaps. Clips in the library but not the sequence do not count. Video outside the song cannot inflate music coverage. Swapping visual dominance alone does not change coverage because the covered time intervals are unchanged.

Visual dominance also determines which clip is eligible to supply audio. Only the dominant clip's audio option is consulted for that interval; hidden clips contribute no audio. The original-song fallback and post-song silence are defined in Clip Audio.

Acceptance criteria:

- **T1:** For a 60-second song with 45 distinct seconds covered, show 75% coverage and visibly mark the remaining 15 seconds as gaps. These are test values, not selected generation-duration limits.
- **T2:** Adding coverage to an already-covered interval does not increase the percentage. Adding previously missing coverage does.
- **T3:** Changes to clip placements/timings update the visible gaps and coverage. Library-only clips do not affect the number.
- **T4:** With music but no included clips, coverage is 0%. Before music duration is known, coverage is not applicable rather than a fictitious percentage.
- **T5:** Label the indicator as coverage. Even 100% does not certify creative quality, review completion, or a successful export.
- **T6:** Place clip B over a time range already occupied by clip A: B is visible throughout their overlap by default. Only one clip's image is shown there; neither blending nor a transition is automatically added.
- **T7:** Use the dominance control to send B behind A: A becomes visible in the overlap, while both placements, their timings, and their source media remain intact. The control can swap the visible winner again without regenerating either clip.

### Clip Audio

The selected song is the arrangement's original-song soundtrack and is used by default. Audio contained in video clips is excluded from the assembled video by default, so successive clips do not introduce inconsistent soundtracks. This remains true even though song audio is supplied to the video generator by default. After the original song ends, that source contributes silence. If the user selected a clip's audio instead, use that clip's existing audio wherever it is the dominant included clip, including portions after the song ends; do not automatically change sources at the music-end boundary.

The learner reports that H3 generally reproduces the supplied music in its output and may mix in natural diegetic sound. When the user chooses a clip's audio, use that existing mixed soundtrack **instead of the original song wherever that clip is dominant**, not on top of it. The application must not play another copy of the original song underneath the clip's mixed audio.

**Overlaps: only the dominant clip can contribute clip audio.** If its audio is enabled, use that soundtrack alone; if disabled, use the original song, or silence after the song ends. Do not fall back to an obscured clip's audio, even if that clip's option is enabled, and do not mix multiple clip soundtracks. Swapping which clip is dominant changes the applicable audio-source choice along with the visible image, but does not change either clip's saved audio-enable setting. A clip's audio may contribute again when it becomes dominant elsewhere. Apply the same rule in preview and export.

This is a source switch using audio already present in the clip, not separate foley generation, stem separation, or independent adjustment of the music and effects embedded in that mix. The choice applies to assembled preview and export; auditioning original clips in the library is a separate presentation detail.

**No additional audio-editing controls are required in the first prototype.** Audio fades, crossfades, levelling, whole-source/output-level adjustments, and mixing foley are later advanced options. Do not add them to the first-build controls or silently process the selected soundtrack with these effects. Existing sound already mixed into a generated clip remains usable through its source-selection option; that does not make the individual foley elements editable. This boundary concerns the assembled/exported soundtrack, not ordinary player controls used to listen to a preview.

The reported H3 behaviour is not yet a verified integration guarantee. In particular, this PRD does not claim that reproduced music is identical to the original or that switches will automatically be seamless. Tool identity, audio-input support, reproduction fidelity, timing alignment, and practical limits need checking in the spec.

**Moved clips: warn, do not prevent.** Keep the clip's initial timeline position as the reference for a moved-position warning. When its current position differs from that initial location, show a warning beside the clip-audio option explaining that its embedded music may not match the new position in the song. The user can still select or retain the clip's audio: a mismatch may be intentional, including dissonant/glitch-oriented editing or an attempt to compensate for a shifted generation. Do not automatically disable the option, move the clip back, regenerate, retime its audio, or block preview/export. The warning is about placement, not a claim that the application has detected an audible error. Frame trimming that preserves the surviving content's song times does not by itself count as a move; separately sliding the trimmed content does.

Acceptance criteria:

- **C1:** A newly included clip contributes no audio to the assembled preview or export unless the user enables its audio, even if the generated source contains an audio track.
- **C2:** The user can enable existing audio for one clip without enabling audio for every other clip.
- **C3:** The same per-clip inclusion choice is reflected in the assembled preview and exported video.
- **C4:** When clip audio is enabled, that clip's existing mixed soundtrack replaces the original song wherever the clip is dominant. The original song is not simultaneously played underneath it; other intervals retain their own selected audio source.
- **C5:** Disabling the dominant clip's audio returns that interval to the original song, not to any obscured clip's audio. Gaps with no clip continue to use the original song. Changing an obscured clip's audio option does not change the current dominant interval's soundtrack.
- **C6:** Moving a clip away from its initial position adds a visible warning alongside its clip-audio option. If clip audio was already enabled, it stays enabled and the warning appears without requiring the user to toggle it again.
- **C7:** The warning does not prevent selecting clip audio, previewing, or exporting. Both preview and export honour the user's source choice at the new position; the application does not silently correct it.
- **C8:** Returning the clip to its initial position clears this moved-position warning. Absence of the warning is not a guarantee that the generator reproduced perfectly aligned audio.
- **C9:** In a dominant clip's post-song portion, the original-song source produces silence, while selecting its clip audio uses that clip's existing soundtrack as supplied. The application neither automatically enables clip audio nor invents or extends sound to fill the section.
- **C10:** If overlapping clips A and B both have audio enabled and B is dominant, use B's audio only during the overlap: neither A's audio nor the original song is mixed underneath it.
- **C11:** If B is dominant with its audio disabled and A's audio is enabled, use the original song during the overlap, or silence beyond the song's end. A's hidden audio does not become a fallback source.
- **C12:** Swapping dominance from B to A applies A's existing audio choice as well as showing A's video. Neither clip's audio-enable setting is toggled by the swap, and preview/export agree on both the visible clip and the resulting soundtrack.
- **C13:** The prototype's editorial audio control is the existing original-song versus dominant-clip-audio choice. It does not expose audio fades, crossfades, levelling, output gain, or separate foley-mixing controls, nor automatically apply those creative treatments. Audio already mixed into a chosen clip is retained as part of that source, not separated into new editable tracks.

Replacement rather than layering, dominant-clip-only audio during overlaps, a non-blocking warning for moved clips, gap-aware defaults using the adaptive 8/4/2/1-beat preset count with the established post-song extension, and silence-versus-clip-audio behaviour after the song ends are settled. Additional audio controls and processing are deferred. No automatic attenuation, added effect tail, or source separation is implied.

### Preview, Black Gaps, and Export

**23 October refinement:** preview must be immediate, live and usable without rendering. Play/pause and scrub inspect current edits; no Render preview action or Update preview after edits checkbox. Export alone renders the full-quality file. Browser playback may be less exact than the exported render, but it follows the same clip, source-offset, audio-source, black-gap and post-song rules.

Users can preview the assembled music video and export a playable video file. **Uncovered intervals are black frames in both preview and export.** Missing clip coverage is not itself an export-blocking error. The song continues through those intervals; the application does not silently shorten the music, freeze a neighbouring clip, loop it, or generate filler.

**Video duration is not capped at music duration.** Retain included post-song video in both preview and export, whether it is one overhanging clip or several further clips generated after the song is fully assigned. Playback/export follows the included arrangement rather than stopping at the song's end or the end of the first overhanging clip. This can support a closing visual or a much longer continuation; it does not automatically add fades, freeze frames, transitions, or a separate outro-editing interface.

Music coverage continues to measure only the original song interval and cannot exceed 100%. Post-song video is outside that denominator; it neither increases music coverage nor counts as a gap in it. In both preview and export, the original-song audio choice becomes silence after the song ends; a selected clip-audio source continues to use the clip's existing soundtrack. Added reverb/effect tails, separate foley, and extra diegetic-sound layers remain later features.

Acceptance criteria:

- **E1:** An interior gap between two clips appears black for the same interval in preview and in the exported file, while the music continues.
- **E2:** Leading or trailing uncovered music behaves the same way. No background-colour or background-image picker is required in this prototype.
- **E3:** A valid project with incomplete clip coverage can export; 100% coverage is not a prerequisite.
- **E4:** The exported file plays independently in VLC and reflects the chosen sequence, timing, and black-gap behaviour.
- **E5:** When the included final clip occupies 16.00–24.00 and the song ends at 18.00 in the timing example, preview and export preserve video through 24.00. They do not stop or truncate that clip at 18.00.
- **E6:** Retaining the six post-song seconds in that example does not alter the music-coverage denominator, inflate the percentage above 100%, or mark those seconds as missing music coverage.
- **E7:** In the 18-second-song/24-second-video example, the final six seconds are silent when the original-song source is selected. With clip audio selected, both preview and export use the corresponding portion of that clip's existing audio instead, without an automatic effect tail or additional sound generation.
- **E8:** Preview and export show the same single dominant clip during each overlap and use its clip audio if enabled, otherwise the original song or post-song silence. This remains true after the user swaps which clip is in front. Neither output silently substitutes blending, a transition, a different priority order, or an obscured clip's audio.
- **E9:** With an 18-second song, included clips covering through 24 seconds, and an additional included clip at 24–32, preview/export retain video through 32 seconds. The fourteen seconds after the song use silence or the dominant clip's enabled audio; they do not increase the music-coverage denominator or percentage. Queued-only placeholders still do not extend rendered output.

Preview/export parity here means the same editorial result, not a new commitment to specialised proxy-preview and high-quality export pipelines. Export format, supported generation durations, resolution, and practical long-output limits need tool-informed definition in the spec. The globally fixed 24 fps rate is settled; other frame rates and rate conversion are outside v1. Continued post-song generation and inclusion are in scope; pre-song intros and general-purpose intro/outro editing remain deferred. No feature-length export has been tested here.

## States and Boundaries

- **Agent provider changed with work outstanding:** existing queued/running requests retain their originally assigned agent and continue unchanged by the switch. Only requests submitted after the change use the new selection. Do not relabel historical work or silently move waiting requests to the new provider.
- **No agent configured or not signed in:** show the Codex/Claude setup choice before generator setup. Selecting or installing a provider does not imply authenticated readiness. An installed agent without sign-in has a provider-labelled error indicator in the navbar, with hover guidance explaining how to sign in. Return to normal activity/queue status only after verified authentication and usability.
- **No tools:** setup is visible in a shared extension of the navbar; the product is responsible for getting the required generation tools ready.
- **No project/content:** the project and generation entry points must be discoverable; empty library/archive/history sections must not pretend that examples are real user results.
- **Setup running or failed:** distinguish activity, readiness, and failure; offer the separate Retry and confirmed Debug paths. Installation and monitoring continue through project switches and page reloads. Incomplete or failed panels remain visible while successfully installed tools move into compact navbar indicators.
- **Setup completed:** each successful step clears its stripes and enables its already-visible navbar indicator. Keep all panels together until every tool is ready, then clear the complete strip at once. Reloads and project switches retain the same grouped visibility rule. Indicators show Idle / not running or Active and the waiting queue length across projects, not merely historical installation success.
- **Generation queued, running, cancelled, or failed:** show queued/running clip placeholders and Cancel. Cancellation stops the work, then offers Restart, Discard, or Restore parameters; the last two remove the cancelled placeholder without automatically generating. Preserve submitted history and distinguish cancellation from failure. Failed attempts retain the established failure details, Retry, and Restore parameters paths.
- **Short or overlong generation interval:** no blanket four-second minimum. Durations over 15 seconds have a non-blocking warning suggesting multiple generations; preserve the range and let the user try it. A one-beat preset can still warn at extremely slow tempos. These advisories do not assert successful tool support.
- **No clips or incomplete coverage:** mark missing coverage; black frames are valid editorial output, not an automatic error.
- **Different song selected:** successful music generation automatically selects the new song with an empty arrangement and marks the previous song unselected. Manual selection of an older song restores its saved arrangement. Keep existing project clips in the library and preserve the previous song's placements for switching back later; reopening does not override a later manual selection. Coverage, timing, preview, and export follow the selected song; in-progress clip requests still complete against their originating song.
- **Overlapping clips:** show one image, with the second/newly placed clip dominant by default. A control swaps front/behind priority without changing timing, discarding either clip, or altering coverage. Only the dominant clip can contribute clip audio; its disabled option means original song or post-song silence, not audio from a hidden clip. Preview/export agree on the visible winner and soundtrack.
- **Clips outlast or start after the music:** retain included post-song intervals in preview/export and continue suggesting further free windows. Show the end-selector advisory when the end exceeds the audio and a matching start-selector advisory when the start is at or beyond its end; neither blocks the choice. The music-end marker and coverage stay tied to the original song. Post-song audio is silence unless the dominant clip's audio is enabled.
- **Moved clip:** mark the clip-audio option with a non-blocking placement warning. Preserve the user's source choice and allow intentional mismatches in preview/export.
- **Archived or deleted material:** recoverable archive and irreversible media deletion are distinct. Archiving a clip or confirming its deletion automatically removes it from the timeline. Coverage and current preview/export update, with any uncovered song intervals rendered black. Restoring an archived clip returns the artifact to the active library unplaced, preserving the current edit rather than undoing the archive's timeline removal. Permanent deletion retains the generation record, thumbnail, and text logs, and adds a deletion event, but the full media is unavailable. Cancelling the confirmation changes nothing; optional history removal is deferred.
- **Project switch/reopen during generation:** generation continues unless explicitly cancelled, retaining its originating project and submitted inputs. Returning shows the queued/running attempt or its outcome; a successful clip is added normally to that project's library and timeline, without duplicate generation or duplicate placement on repeated reopening. Cancelled placeholders remain cancelled, and an attempt that failed while the user was away uses the existing failure presentation. Shared installation and monitoring continue independently of the selected project.
- **Shared repair authority:** the debug confirmation discloses autonomous changes beyond the working directory; neither the project boundary nor directory selection is a security sandbox.
